# 第三块：修改、验证与补丁

## 当前机制

模型提出修改请求，工具在 Docker 里的**工作副本**上执行。应用另外保存启动时的
**基线副本**，基线不挂载进容器，因此模型命令不能把它一起改掉。

```text
原仓库 → 会话起点 → 基线（应用保管，不挂载）
                  → 工作副本（容器内可修改）

模型 → 读取 → 编辑 → 运行测试 → 看结果 → 决定继续修改还是回答
应用：基线与工作副本比较 → 显示差异 / 导出 .patch
```

三个概念要区分：
- **编辑成功**：指定文本已经被替换，不代表程序正确。
- **命令退出码为 0**：这条命令成功退出；如果运行的是测试，说明这些测试通过。
- **需求完成**：还要确认用户要求是否全部实现，测试通过不自动结束 Agent 循环。

## 真实执行证据

本地 Qwen 在一个有错误的小项目中完成了：
1. 读取 calculator.py 和测试文件。
2. 执行 `python -m unittest -v`，看到 3 个测试失败。
3. 将 `return a - b` 改为 `return a + b`。
4. 再运行相同测试，3 个全部通过。
5. 查看差异并导出补丁。

原始小项目仍然包含减法错误；模型修改的是副本。测试文件没有被改动。
导出的补丁已应用到另一个临时 Git 仓库，内容与修复后的副本逐字节一致。

本次模型在导出后给了空白最终答复。程序现已对这种情况明确提示，并展示实际工具证据，
不会假装收到模型的完成说明，也不会重跑编辑或命令。空答复根因尚未确认。

## 代码位置

- `container_worker.py`：精确编辑、命令执行与退出码/超时结果。
- `coding_backend.py`：编码工具和应用工具的接线。
- `patches.py`：基线、文本差异、应用决定的补丁路径。
- `cli.py`：显示结果及处理空答复、Ctrl+C。

工具出错后仍将反馈交回模型。编辑只替换唯一匹配的旧文本，匹配失败会拒绝，
避免模型用过时内容静默覆盖文件。命令不自动重试；超时、取消可能已经产生部分修改。
当前退出后保留文件和日志，但还没有恢复会话功能。

## 用户实验（待执行，助手没有代做）

范围只限你自己新建的练习目录及其中的两个小文件，不修改本项目实现。
准备一个有一处简单计算错误的函数和一个标准库 unittest 测试，初始化独立 Git 仓库。
按默认直接模式启动 CLI 并选择练习仓库，让模型修复、运行测试、查看差异；补丁可选。
如要重做本文历史上的副本实验，显式使用 `uv run cli-rb --isolated`。

先预测：模型说“测试通过”之后，你直接打开原仓库的函数，看到的是旧内容还是新内容？
再检查原文件与会话基线：默认模式下原文件已改变、基线保留起点。隔离模式下原文件不变、工作副本改变。

前提：Docker 和 LM Studio 正在运行。默认镜像只有 Python 标准库，别用依赖 pytest 的练习。
