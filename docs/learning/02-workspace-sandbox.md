# 第二块：从内存文件到真实仓库副本

## 当前要理解的一个变化

第一块里，工具在 Python 字典里找到两行文字。现在，工具通过 Docker 在一个
单独的仓库副本里读取真正的代码。模型仍然只看到工具说明、请求参数和返回消息。

可以把副本理解为给助手的一份复印件。原件保留在原处，助手的工具只能接触复印件。
第二块进一步把复印件也设为只读；下一块再考虑如何允许安全修改。

## 调用路径

```text
用户选择仓库、确认范围
    → create_snapshot：读取当前源码并筛选、复制
    → build_agent：给模型 read_file / list_files / search_files
    → 模型请求工具
    → DockerReadBackend：启动受限容器，只挂载副本
    → container_worker：执行读取并返回文本
    → LangChain ToolMessage
    → 模型继续调查或回答
```

模型服务仍运行在宿主机，只有工作区工具在禁网容器中运行。因此禁网不会切断
应用与 LM Studio 的模型请求。宿主机应用负责调用两者，并把工具文本交回模型。

这不是模型随意拼接 shell 命令：三个工具只接收文件路径、搜索文本和分页参数。
应用通过固定参数启动容器，工具参数以 JSON 传入固定的读取程序。

## 观察证据

真实 Qwen 已读取 `src/cli_rb/agent.py` 和 `src/cli_rb/workspace.py`，
回答了 workspace 参数如何切换工具集合，并引用源码行号。
问答完成后比较 24 个原始源文件的哈希，全部一致。

容器测试还验证了：uid 65534、无 capabilities、禁止提权、无法访问外部网络、
不能写入副本、没有 Docker socket。模拟测试和真容器测试的区别见 STATUS.md。

代码入口：
- `snapshot.py`：副本与筛选清单。
- `docker_backend.py`：容器权限、资源限制、超时和工具日志。
- `container_worker.py`：容器内的路径检查、列文件、搜索、分段读取。
- `workspace.py`：模型可见的工具参数和说明。

## 你可以运行

在项目目录设置 `CLI_RB_MODEL=qwen/qwen3.5-9b`，运行 `uv run cli-rb`，
选择本项目目录并确认范围。输入“解释这个项目的 Agent 循环，给出文件和行号”，
Alt+Enter 提交，观察模型如何使用工具。

## 用户小实验（已完成）

范围仅限你新建的 `learning-probe.txt`：
先在原仓库创建这个文件，写入 `version one`，启动新对话并让模型读取。
然后手动把原仓库文件改成 `version two`，在同一对话让模型再次读取。
先预测读到哪个版本，再观察结果。这能区分“会话副本”与“实时读取原仓库”。
实验完成后自行删除这个练习文件。此实验不要求修改实现代码。

用户已完成实验：原文件由 1 改为 2 后，同一会话仍读到 1，确认读的是启动时副本。
经过问答已理解：CLI 请求 LM Studio，容器内执行工具实际操作；工具包装函数在宿主机，
容器不需要模型密钥；路径越界由程序强制拒绝，不能只靠模型自觉。

第二块完成时尚无编辑/命令/补丁功能；这些能力在第三块实现。会话恢复仍未实现。
