# 第一块：一次工具往返

## 核心机制

用户提出读取文件的请求。模型本身不打开文件，而是返回带名称、参数和 ID 的工具调用。
LangChain 根据名称调用 Python 工具函数。函数把后端结果返回，框架将其包装为
`ToolMessage`，通过 `tool_call_id` 关联原请求。下一轮模型同时看到用户消息、
自己的工具请求和工具结果，再决定继续行动还是回答。

框架负责调度；我们补充模型配置、工具能力、后端边界、错误文本与终端展示。
读取成功不强制结束。普通问候也不强制调用工具。

## 观察

运行 `uv run cli-rb demo`，观察三类事件：

```text
模型请求工具：read_file {'path': 'README.md'}
工具返回 [read_file]：1: # CLI Rb
2: 当前能力：演示模型与只读工具的往返。
Agent：演示模型收到的工具结果：...
```

这是脚本模型的公开消息，不是隐藏推理。运行路径：
`cli.demo → build_agent → create_agent → read_file → FixtureBackend → ToolMessage → 模型`。
`tests/test_roundtrip.py` 另外检查了下一轮模型确实收到工具错误，并能改参数继续读取。

真实模型尚未验证；等 LM Studio 就绪后运行 `uv run cli-rb smoke`。

可以用自己的话解释：**模型返回 `read_file` 后，究竟谁读取内容，又是谁决定下一步？**
