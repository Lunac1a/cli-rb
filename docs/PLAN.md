# 全新项目计划：对话式 CLI 编码 Agent 与同步学习

> 2026-09-24 方向调整：默认 human-on-the-loop，普通本地编辑自动进行，关键操作 human-in-the-loop。此版本取代此前“默认副本、仅交付补丁”的约定，详见 ADR 0004。

## 1. 目标与持续原则

从零建立独立项目，开发一个通过自然语言使用的 CLI 编码助手。首版支持三个场景：

- **理解仓库**：搜索、阅读代码，解释实现。
- **修改代码**：根据需求调整相关文件。
- **修复问题**：调查错误、修改代码、运行验证，并根据结果继续处理。

项目同时实现两个目标：**交付可用、可评测的产品；让开发者理解核心机制，并能独立修改和排查问题。**

架构思想持续对齐 Codex、Claude Code 等成熟编码 Agent 的公开设计：

- 模型根据任务与反馈动态选择动作。
- 工具提供真实环境反馈，运行层保证权限、隔离、预算和持久化。
- 按需获取与管理上下文，支持连续协作和可检查的代码变更。
- 产品完成判断与外部能力评分分离。
- 优先采用成熟框架，自研部分聚焦产品需求和集成边界。

对齐不意味着照搬功能、语言或内部实现，也不假设参考产品使用 LangChain。每阶段记录关键架构决策、公开参考依据及必要的偏离原因。

首版不做多 Agent、专门的计划管理工具、插件/MCP、联网搜索、GUI 和跨会话长期记忆。模型可以用文字说明计划。

## 2. 产品体验与技术架构

### 对话体验

启动后直接进入对话界面，基本操作无需记忆命令：

```text
你：解释一下这个项目的登录流程。
Agent：搜索、阅读，然后解释。

你：增加邮箱格式校验。
Agent：修改代码、运行验证，展示结果。

你：看看修改内容，再导出补丁。
Agent：展示差异并导出。
```

首次使用通过引导选择仓库、配置模型并确认执行范围；后续启动可以选择新会话或恢复已有会话。

支持多行输入、流式回复和 Ctrl+C 取消。首版不支持执行中的实时插话，用户可取消后补充要求。评测使用内部非交互入口，普通用户无需接触。

### 技术选择

| 部分 | 选择 |
|---|---|
| 开发环境 | Python 3.12、uv |
| Agent 循环 | LangChain `create_agent` |
| 常见扩展 | LangChain 中间件 |
| 持久化与中断 | LangGraph、SQLite checkpointer |
| 终端交互 | Rich、prompt-toolkit；Typer 仅处理启动和内部入口 |
| 执行环境 | Docker Linux 容器 |
| 模型接入 | 本地及云端 OpenAI-compatible API |

使用统一循环：

**用户消息 → 模型决定下一步 → 程序执行工具 → 返回结果 → 继续行动或回答。**

不强制生成 Spec，不固定工具顺序，不因测试通过自动结束。模型可以直接回答、调查、澄清需求或修改代码。

首版提供列文件、内容搜索、分段读取、创建/编辑文件、执行命令五类工作区工具。测试和构建属于命令执行。“查看变更”“导出补丁”通过受控应用工具实现。

### 扩展边界

- Agent 与工具分离，增加工具不改核心循环。
- 工具与执行环境分离，统一通过沙箱后端操作工作区。
- 会话状态与存储分离，复用框架持久化，允许以后增加计划等状态。
- 执行与展示分离，运行层输出事件，CLI 负责呈现。
- 交互和评测复用同一个 Agent，只替换输入输出与配置。

优先使用框架接口，只增加必要适配，不提前建设通用插件系统。

## 3. 模型、沙箱与可靠性

### 模型和预算

开发测试与首轮评测使用本地模型，不自动回退到付费 API。

初选 **Qwen3.5-9B Q4_K_M + LM Studio**，面向 16GB 显存。先验证结构化工具调用、多轮反馈、流式输出和显存稳定性，再固定模型文件、服务版本及采样参数。

初始限制：

- 16K 上下文，单次最多输出 2K tokens。
- 同时运行一个任务；每任务最多 50 次模型调用、100 次工具调用、10 分钟。
- 单条命令默认超时 60 秒，模型请求超时 120 秒，均受任务剩余时间限制。
- 瞬时模型接口错误最多重试一次；有副作用的工具不自动重试。
- 长输出保存为日志，向模型提供截断说明和继续读取的位置；上下文接近上限时使用框架摘要机制。

### 沙箱与权限

默认直接编辑用户授权的本地工作区；每个会话保存筛选后的起点基线，包含未提交源码。保留 --isolated 副本模式。直接模式屏蔽 Git 元数据、凭据、依赖和应用记录；普通命令只读，需写入的命令及删除已有文件请求授权。

启动时确认执行范围，之后沙箱内的读取、修改和命令执行自动进行。容器非 root、非特权运行，限制资源，默认禁止网络，不提供 Docker 管理接口或宿主机敏感目录。

依赖在准备阶段安装。准备失败明确报告，不自动改为宿主机执行或放开网络。

默认修改立即在本地仓库生效，展示差异供用户随时检查，补丁导出改为可选归档。隔离模式仍不自动应用。导出路径由应用决定。推送、发布不属于当前工具能力；未来接入时需要明确授权。

### 会话与恢复

- 同一会话保留上下文、基线与当前工作区。
- Ctrl+C 取消模型请求和命令进程树，保留已发生的修改。
- 检查点、基线、可选副本和日志持久保存，容器可以重建。
- 恢复时先检查结果不确定的动作，不静默重放。
- 分开记录运行结束原因、验证证据和外部评分。
- 回复说明完成内容、验证结果和未确认事项；没有运行测试时明确说明。
- 密钥不进入沙箱或日志；数据默认保存在本机，不强制使用云端追踪。

## 4. 实施与学习同步推进

### 每个功能块的合作方式

采用 **“理解 → 实现 → 观察 → 复述 → 动手”** 的固定节奏：

1. **实现前讲清机制**：只解释当前功能解决的问题、输入输出、框架职责和需要补充的部分。
2. **实现一个完整小功能**：每次围绕一个可运行行为推进，避免一次生成整个项目。
3. **观察真实执行**：检查实际模型请求、结构化工具调用、执行结果及下一轮输入；不要求查看模型隐藏推理。
4. **由用户复述理解**：用户用自己的话说明流程，助手针对具体误解补充解释，一次聚焦一个问题。
5. **安排一个小改动或故障实验**：例如修改工具参数、制造超时或拒绝操作；先预测，再运行和解释结果。

助手承担主要实现和例行验证；用户参与关键设计理解，并亲手完成小范围练习。用户练习的文件范围提前明确，助手不抢先完成；练习可按用户要求跳过，不作为强制考试。

学习默认只关注当前阶段，不要求先读完框架源码。每块留下简短记录：核心概念、调用路径、运行证据、实验结果和待理解问题。学习材料放在项目文档中，不进入产品运行流程。

### 阶段安排

| 阶段 | 工程交付 | 学习重点与完成标志 |
|---|---|---|
| **1：最小闭环** | 独立项目、模型连接、对话界面、容器及基础工具 | 先理解一次“模型请求工具—执行—返回”的往返，再完成仓库问答、修改、测试和补丁导出 |
| **2：可靠的连续使用** | 流式进度、取消、恢复、上下文、预算和日志 | 理解状态、检查点与工作区的关系；能解释并演示中断后的恢复 |
| **3：外部评测接入** | SWE-bench 环境、补丁输出、官方评分和归档 | 理解任务内验证与独立评分的区别；能沿一题的记录定位失败环节 |
| **4：冻结实验与交付** | 对照实验、报告、安装说明和演示 | 理解公平比较与结果边界；能独立讲解架构、运行一次任务并分析结果 |

每阶段完成后，整理工程验收证据、架构决策和学习记录，再提交。默认先完成该阶段回顾，再进入下一阶段；用户明确要求连续推进时可调整节奏。

阶段 1 先验证 Docker、WSL 和模型实际可用性，不假设环境已经准备完成。

## 5. 测试、评测与最终交付

### 工程验收

使用模拟模型稳定验证集成边界，再使用本地真实模型验证完整闭环。重点覆盖：

- 普通回答、只读调查不强制修改或测试。
- 已有测试通过不截断未完成的新增需求。
- 工具错误能返回模型，越界访问被拒绝。
- 直接模式编辑在原仓库生效，普通命令不可写；关键操作授权边界得到验证。隔离模式不影响原仓库。差异包含新增、修改和删除。
- 超时、取消、预算退出及恢复正确。
- 不确定的命令不会在恢复时静默重跑。
- 日志、验证证据和用户报告一致。

不重复测试框架内部实现，也不为了教学增加生产代码复杂度。

### 能力评测

使用 SWE-bench 官方评测器独立评价补丁，不采信 Agent 的完成声明。

- 开发集中的 3 道题用于集成验证，不计入正式成绩。
- 正式固定 SWE-bench Verified 的 20 道题：按实例 ID 排序，以 seed 42 抽样，在针对任务调优前保存清单。
- 对照为 mini-SWE-agent，使用同一本地模型、任务、上下文上限和每题 10 分钟预算，公开工具及提示词差异。
- 每系统每题一次，共 40 次正式尝试，顺序执行，总运行上限 8 小时。
- 参考补丁、官方评分测试和评分日志不进入求解上下文。
- 不按结果换题或挑选重跑；环境错误单独报告，保留全部任务状态。
- 报告解决数量与比例、耗时、token 用量、失败分类和逐题证据，明确标注本地量化模型的子集成绩。

最终交付包括：**对话式 CLI、可复现沙箱、会话恢复、自动化测试、固定模型配置、架构与学习记录，以及独立评测报告。**

项目以流程可靠、证据完整、架构原则落实为工程验收标准；学习以能够解释实际流程、修改小功能和分析失败为目标，不预先承诺基准解决率。
