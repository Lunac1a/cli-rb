# 0004：默认直接编辑，关键操作授权

用户选择 human-on-the-loop：普通本地修改自动进行，用户随时查看与干预；关键动作需要 human-in-the-loop。此决定更新 0002/0003 的默认副本约定，不改变那些历史验收事实。

默认 `direct` 会话保存当前筛选源码作为基线，Docker 工具读写真实仓库。编辑工具保持先读后改、唯一旧文本匹配；人工后续修改对下一次读取可见。`--isolated` 保留原来的独立副本行为。

普通命令以只读工作区挂载运行，仍可写临时目录。需要写入工作区时，`run_write_command` 展示完整命令并申请一次授权；删除已有文件也需要授权。通过创建工具在本会话新建的文件允许直接删除。非交互入口无授权回调时拒绝关键动作。授权写命令涵盖该命令可能进行的修改和删除，不做 shell 黑名单式安全推断。

容器继续禁网、非 root、限制资源且不挂载 Docker socket。每次执行前重新扫描，Git 元数据、忽略文件、常见凭据及运行记录用只读空挂载屏蔽；工具路径检查也拒绝访问。路径含链接或 Windows 重解析点时拒绝直接挂载。模型不拥有授权回调，无法通过工具参数自行授予权限。

直接模式不提供自动撤销；取消/超时保留已经写入的内容。差异相对会话起点而非 Git HEAD，也可能包含用户或其他程序的同期修改。导出补丁只是归档，不需要再次应用。推送、发布当前没有实现；未来接入时另设明确授权边界。

边界：凭据识别仅覆盖已知规则；没有跨进程文件锁，不能抵御其他程序恶意并发替换目录/链接。避免同时编辑同一文件。项目依赖仍须提前放入可信镜像，已有宿主机依赖目录被屏蔽。可写命令不保证不会破坏仓库内源码，因此只在确有需要时授权。人工验收仍负责确认结果是否符合需求。
